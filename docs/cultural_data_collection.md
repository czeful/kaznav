# Культурные предметы: какие данные собрать (варианты B и C)

Этот документ — для тех, кто собирает фото и 3D-модели. Нужен он для проверки гипотезы H2: казахские слова
для культурных предметов (қазан, сандық, домбыра…) модели понимают хуже обычных, и перевод через английский
это усиливает (`docs/analysis_plan.md` §1, §5).

## Главное правило: пары

**У каждого культурного предмета есть «контрольная пара»** — обычный предмет того же назначения и похожей формы:

| культурный | пара (обычный) | | культурный | пара (обычный) |
|---|---|---|---|---|
| қазан | кастрюля (cooking pot) | | самауырын | чайник (kettle) |
| сандық | комод / ящик (chest of drawers) | | кесе | чашка (cup) |
| кебеже | шкафчик (cabinet) | | бесік | детская кроватка (crib) |
| домбыра | гитара (guitar) | | дастархан | обеденный стол (dining table) |
| сырмақ / текемет | ковёр (rug) | | көрпе | одеяло (blanket) |
| түскиіз | картина / гобелен на стене (wall hanging) | | торсық | фляга (flask / water bottle) |

Пары нужны, потому что сравнение «культурное против обычного» должно отличаться **только словом**, а не
качеством фото, ракурсом или способом вставки в сцену. Каждую пару снимают и вставляют одинаково.
Список можно менять до заморозки плана; добавляйте пару целиком или не добавляйте.

## Вариант C — фотографии (язык и верификация)

**Сколько.** На каждую категорию (и культурную, и её пару):
- **минимум 20 фото**: 15 для теста и 5 для dev (настройка);
- **разные экземпляры** предмета (не 20 снимков одного қазана), разные комнаты, освещение, ракурсы.

На 12 пар это примерно 480 фото.

**Как снимать:**
- **половину фото — низко, на высоте 15–30 см от пола**, как видит робот-пылесос; половину — с обычной
  высоты;
- предмет целиком в кадре и занимает заметную часть кадра; рядом могут быть другие вещи, как в жизни;
- без людей и лиц, без документов и номеров;
- лучше снимать самим. Чужие фото — только с открытой лицензией (CC0 или CC-BY), с записью автора и ссылки.

**Как оформить** — одна строка на фото в таблице `data/cultural_photos/photos.csv`, фото рядом с ней. Шаблон —
`docs/templates/cultural_photos_template.csv`. Папка `data/` не попадает в git: фото и модели хранятся
локально. Колонки:

| колонка | пример | что это |
|---|---|---|
| `photo_id` | `kazan_017` | уникальный код |
| `file` | `kazan_017.jpg` | файл в `data/cultural_photos/` |
| `category` | `қазан` | категория из таблицы пар |
| `pair` | `cooking pot` | её пара |
| `word_type` | `cultural` / `universal` | культурная или контрольная |
| `split` | `test` / `dev` | 15 test + 5 dev на категорию |
| `viewpoint` | `low` / `normal` | низкая (15–30 см) или обычная съёмка |
| `instance` | `kazan_A` | код физического предмета: одинаковый у фото одного и того же қазана |
| `source` | `own` / ссылка | своё или откуда взято |
| `license` | `own` / `CC-BY-4.0` | лицензия |
| `author` | `A01` | код автора, как в командах |

**Команды** к этим категориям пишут носители языка по тем же правилам, что и для HM3D
(`docs/command_authoring.md`): kk, kk-ru и en, рецензия вторым носителем, минимум 10 test-команд на категорию.
Таблица для заполнения — `commands/natural/cultural_pairs_sheet.csv`: 24 категории × 12 строк.

## Вариант B — 3D-модели (навигация)

Модели вставляются в сцены HM3D (на пол, на стол, на стену), и робот ищет их по команде.

**Сколько:** на каждую категорию (культурную и пару) **2–3 разные модели**, лучше от разных авторов.

**Требования к модели:**
- формат GLB или GLTF (OBJ тоже подойдёт), не больше ~20 МБ, с текстурами;
- **реальный размер** (подписать габариты в см, если в модели масштаб условный);
- лицензия CC0 или CC-BY: источник (Sketchfab, Objaverse, Poly Haven и т. п.), автор и ссылка — в таблицу;
- предмет похож на настоящий, а не на мультяшный.

**Таблица** `data/cultural_assets/assets.csv` (шаблон — `docs/templates/cultural_assets_template.csv`): `asset_id, file, category, pair, word_type, size_cm (Ш×Г×В),
placement (floor / table / wall), source_url, license, author`.

## Что сделаю я после сбора

- проверку таблиц (пары, лицензии, разбиение dev / test);
- для фото — замер по языкам: называет ли разобранная команда предмет, и точность верификации на «своём»
  фото и на фото пары (трудный отрицательный пример);
- для 3D-моделей — вставку в сцены HM3D, генерацию эпизодов, разметку для метрик;
- анализ H2: разница kk − en на культурных минус та же разница на парах, с доверительными интервалами по
  категориям (план анализа §5).
